## 1. Convención Estricta de Estados

Conforme a las reglas de control de calidad del proyecto, cada escenario contable se clasifica exclusivamente bajo una de las siguientes etiquetas:

| Etiqueta de Estado | Criterio de Asignación |
| :--- | :--- |
| **`IMPLEMENTADO Y PROBADO EN POSTGRESQL REAL`** | Componente UI operativo + lógica de negocio en backend + persistencia en base de datos PostgreSQL real certificada en suite de pruebas de integración física. |
| **`IMPLEMENTADO Y PROBADO SOLO EN pg-mem`** | Lógica de negocio completa y asiento generado cuadrado y verificado en pruebas automáticas unitarias / en memoria (`pg-mem` o mocks), pendiente de certificar sobre motor físico PostgreSQL. |
| **`IMPLEMENTADO SIN PRUEBA`** | Código escrito en frontend o backend pero sin cobertura automatizada de aserciones. |
| **`PARCIAL`** | Funcionalidad soportada de forma incompleta (ej. soporta base e IGV pero carece de tributos adicionales, o backend soporta campos que la UI no permite ingresar). |
| **`NO IMPLEMENTADO`** | El flujo o cálculo no existe actualmente en el código o requiere desarrollo desde cero. |
| **`SUPUESTO A VALIDAR`** | Tratamiento contable, fiscal o de cálculo que no emana de una norma tributaria expresa y requiere ratificación por parte del contador o tributarista. |

## 4. Conclusiones y Brechas Críticas Identificadas para el Plan de Acción

1. **Subdiario 01 (Compras):**
   - La arquitectura de cálculo, validaciones paramétricas (18%, 10%, 14%), bloqueo de incompatibilidades (retención + percepción) y asiento completo con cuentas PCGE a 5 dígitos (60111, 40111, 4212, 4213, 40114, 40113, 20111, 6111) está completada en un **83%** en memoria (`pg-mem`).
   - Brechas pendientes de cierre: Soporte para Notas de Crédito/Débito con enlace de comprobante original y facturas de no domiciliados (tipo 91).
2. **Subdiario 02 (Ventas):**
   - Es el subdiario con mayor rezago (**55% no implementado**): La interfaz actual solo presenta campos para Base, IGV y Total, careciendo de entradas para Operaciones Exoneradas, Inafectas, Exportación, ISC, ICBPER, Percepciones de clientes y desglose de Detracción SPOT del cliente.
3. **Subdiario 04 (Pagos / Tesorería):**
   - Falta el módulo de emisión de **Comprobantes de Retención Electrónica (CRE - Tipo 20)** cuando una compra a crédito supera los S/ 700 y se cancela en tesorería.
4. **Subdiario 07 (Planillas):**
   - Es el módulo más maduro y robusto del sistema: cuenta con certificación sobre **PostgreSQL real** con multi-tenancy RLS, persistencia física de tablas de nómina y exportación en PDF.
