## 1. Convención Estricta de Etiquetas de Estado

De acuerdo con las reglas de control de calidad del proyecto, cada escenario contable se clasifica de forma exclusiva bajo una de las siguientes etiquetas:

| Etiqueta Permitida | Criterio de Asignación |
| :--- | :--- |
| **`IMPLEMENTADO Y PROBADO EN POSTGRESQL REAL`** | Reservada estrictamente para flujos certificados sobre una instancia física de PostgreSQL mediante la ejecución documentada de la suite `npm run test:pg`. *(Ninguna prueba se etiqueta aquí hasta contar con la salida de `test:pg`)*. |
| **`PROBADO SOLO EN pg-mem`** | Asiento o regla probada contra el emulador `pg-mem` en pruebas unitarias específicas de motor relacional en memoria. |
| **`PROBADO CON MOTOR EN MEMORIA`** | Funcionalidad implementada en servicios/UI y validada con aserciones automatizadas sobre almacenes de memoria (`_MEMORIA` / mocks). |
| **`IMPLEMENTADO SIN PRUEBA`** | Código existente en interfaz o backend pero sin cobertura de aserciones automatizadas dedicadas que citen explícitamente su ID. |
| **`PARCIAL`** | Funcionalidad soportada de forma incompleta (ej. soporta base e IGV pero carece de tributos adicionales o comprobante de referencia). |
| **`NO IMPLEMENTADO`** | El flujo o cálculo no existe en el código o requiere desarrollo desde cero. |
| **`SUPUESTO A VALIDAR`** | Criterio o dinámica contable no deducible de una norma tributaria expresa que requiere ratificación por parte del contador. |
